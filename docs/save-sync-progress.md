## Plan

All eight steps landed on 2026-10-03; see Done. Each step: what done looks like.

1. Claim names round-trip in every binding. A save name with bytes outside printable ASCII comes back in `unowned` in a form the same binding accepts in `claimed`, and the claim moves the save. Python and Kotlin tests prove it with a Saturn volume whose save name holds such bytes.
2. Kronos and Yaba Sanshiro layout rows. Kronos libretro default (`kronos/saturn/{stem}.ram`, `{stem}-ext{size}.ram`) and `kronos_use_beetle_saves` (`{stem}.bkr`, `.bcr`); Yaba Sanshiro libretro `yabasanshiro/backup.bin`, shared, 8 MiB expanded. Sync tests collect and restore through each, and the Yaba volume keeps its expanded form.
3. Dreamcast sync. A VMU kind over the existing `card_dreamcast` code, the flycast libretro rows (`reicast_per_content_vmus` disabled: shared `dc/vmu_save_A1.bin`; `VMU A1`: `{gameId}.A1.bin`) and flycast standalone (`{gameId}_vmu_save_A1.bin`). Units are the A1 VMU. Tests: per-game round trip, shared VMU swap with holding.
4. GameCube sync. Dolphin raw card (`GC/MemoryCardA.{region}.raw`) as an id kind; Dolphin GCI folder mode (`GC/{region}/Card A/*.gci`) where each `.gci` is a member. Unit: the game's `.gci` files, SINGLE or a flat zip. Tests: raw card round trip keeping other games, GCI folder round trip, raw to folder and back.
5. Save-name table. Product code to save-name prefixes, consulted after learned owners and before the user, for codes the request carries in `game_ids` or `title_id`. Seed rows only where a sample or our own disc scan confirms both the code (read from the disc header in the ROM corpus) and the name. Tests: a table hit moves a save into the unit, a shared name stays unowned, a game without a row behaves as before.
6. Companions for stitching. The request lists companion games, each with ids and its unit. Restore builds the target with the main game's saves plus each companion's; collect returns the main unit without companion saves and a unit per companion holding the saves it owns. Refuses with the overflowing save named when they don't fit. Tests per platform kind: PS1 (ids), Saturn (volumes).
7. Kotlin compiles. A scratch Gradle project including `bindings/android` builds `compileReleaseKotlin` with the working tree's sources.
8. PCSX2 folder cards. A layout row for the standalone PCSX2 family (`memcards/Mcd001.ps2/` as a folder card), collect packing the game's save folders into the per-game `.ps2` unit, restore unpacking into folders (`_pcsx2_index`, `_pcsx2_meta*`), writing a full `_pcsx2_superblock` when it's missing or unusable, and removing files of the game's folders the unit lacks. Tests against the AetherSX2 and ARMSX2 samples.

## Decisions

- Restore never uploads, so on a shared volume it refuses with `SIGIL_ERR_UNCOLLECTED` instead of collecting first. The roadmap was updated to match.
- Volume units are raw: `backup.ram`, `cart.ram`, or `<stem>.zip` with both.
- genesis_plus_gx region: forced option, then content name tag, then the only file present.
